## Part 2: Technical Integration Blueprints

### 1. The Core Extension: Model Context Protocol (MCP) Server
The **Model Context Protocol (MCP)**, open-sourced by Anthropic, is the modern standard for connecting AI clients (Claude Desktop, Claude Code CLI, Cursor, Windsurf) to local tools and data.
*   **Architecture**: Written in **Go**, utilizing stdin/stdout JSON-RPC communication. It connects natively to the local LBMesh SQLite database (`state.db`) and socket engine.
*   **Exposed AI Tools**:
    *   `lbmesh_status`: Retrieves active containers, metrics, and mapped port reservations.
    *   `lbmesh_up`: Invokes the dynamic orchestration engine to launch a target recipe.
    *   `lbmesh_down`: Tears down local workspace containers and prunes networks.
    *   `lbmesh_list_recipes`: Outputs the consolidated cascading recipe catalog.

Expose LBMesh container orchestration tools directly to your local AI clients (Cursor, Claude Desktop, Claude Code).

Add the following configuration block to your Claude Desktop configuration file:

    "lbmesh": {
      "command": "lbmesh",
      "args": ["mcp", "start"]
    }
  }

## Available AI Tools

- `lbmesh_status`: View running services, scopes, and active port bindings.
- `lbmesh_up`: Spin up any recipe (e.g., PostgreSQL, Redis, custom taps) with automatic port broker remapping.
- `lbmesh_down`: Teardown active container services and prune bridges.
- `lbmesh_list_recipes`: View available Cascading Recipe Registry templates.
```

### 2. Cursor `.cursorrules` Blueprint
```markdown
# LBMesh Cursor Rules

These rules configure Cursor's AI chat, Composer, and inline edit interfaces to successfully author and manage local LBMesh environments.

## Directory & Schema Standards
- Always author LBMesh local configurations in `.lbmesh/recipe.yaml`.
- The YAML file must adhere strictly to the `recipe.v1.yaml` schema:
  - Version must be `"v1"`.
  - Must define resources (`min_memory_mb`, `recommended_memory_mb`, `min_cpus`).
  - Declare ports with preferred host mappings (e.g., `container: 5432, preferred_host: 5432`).

## Execution Best Practices
- Never write hardcoded host ports into source files. Always use environment substitution (e.g., `${HOST_PORT}`) and read output variables from the dynamic `.env` file generated by LBMesh.
- To audit recipes, instruct the user to run `lbmesh recipe lint <file>`.
```

### 3. Claude Code Prompt Blueprint
```markdown
# LBMesh System Instructions for Claude Code

When assisting developers in an LBMesh-enabled project:
1. **Tool Usage**: If the LBMesh MCP server is connected, use `lbmesh_status` before recommending container actions.
2. **Resource Integrity**: Before starting a recipe, verify if the user's local hypervisor (e.g., Podman machine) has sufficient memory capacity. 
3. **Collision Safety**: Emphasize that ports are negotiated dynamically. Remind the developer that they do not need to manually change ports; the LBMesh broker guarantees zero binding conflicts.
```
